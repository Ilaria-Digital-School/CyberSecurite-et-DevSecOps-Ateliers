# Repérer les erreurs dans une trame

**Rappel théorique** Une trame Ethernet (couche 2 du modèle OSI) est une unité de données structurée transmise sur un réseau local. Elle se compose de plusieurs champs obligatoires : le préambule (7 octets de synchronisation), le Start Frame Delimiter (SFD, 1 octet), l'adresse MAC destination (6 octets), l'adresse MAC source (6 octets), le champ EtherType/Length (2 octets indiquant le protocole encapsulé ou la taille de la payload), la payload (de 46 à 1500 octets) et le Frame Check Sequence ou FCS (4 octets, checksum CRC-32 permettant de détecter les erreurs de transmission). Si l'un de ces champs est absent, mal formaté ou incohérent, la trame est considérée comme corrompue ou malformée et doit être rejetée. Les erreurs les plus fréquentes dans une trame sont : une adresse MAC mal formée (longueur incorrecte, caractères invalides), un EtherType inconnu ou incohérent avec la payload, une payload trop courte (runt frame, inférieure à 46 octets sans padding) ou trop longue (giant frame, supérieure à 1500 octets), un FCS invalide (la valeur calculée ne correspond pas à la valeur déclarée), ou encore des champs manquants. En cybersécurité, identifier ces anomalies est fondamental : une trame malformée peut être le signe d'une attaque par fuzzing, d'un empoisonnement ARP, ou d'une tentative d'évasion d'un IDS.
