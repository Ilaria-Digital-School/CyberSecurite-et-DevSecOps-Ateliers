# Scanner des ports avec Nmap (niveau débutant)

--- RAPPEL THÉORIQUE --- Avant de plonger dans la pratique, rappelons les bases. Un port est un identifiant numérique (de 0 à 65535) associé à un service réseau sur une machine. Lorsqu'un paquet TCP ou UDP arrive sur une machine, le système d'exploitation utilise le numéro de port pour savoir quel processus doit le traiter : le port 80 pour HTTP, 443 pour HTTPS, 22 pour SSH, 53 pour DNS, etc. Tu as manipulé ces notions dans les activités précédentes sur TCP/UDP et le multiplexage. Nmap (Network Mapper) est l'outil de référence pour la reconnaissance réseau. Son principe de base est simple : il envoie des paquets vers une cible et analyse les réponses pour déterminer si un port est OPEN (service en écoute), CLOSED (port joignable mais sans service) ou FILTERED (un pare-feu bloque la réponse). Par défaut, Nmap effectue un scan TCP SYN (half-open scan) : il envoie un paquet SYN, et si la cible répond SYN-ACK, le port est ouvert — sans compléter le handshake TCP complet que tu as pratiqué avec netcat. Erreurs fréquentes des débutants : scanner des cibles sans autorisation (illégal !), confondre un port FILTERED avec un port CLOSED, ou ignorer les informations de version de service pourtant cruciales pour identifier des vulnérabilités. Mental model à retenir : Nmap, c'est comme frapper à toutes les portes d'un bâtiment et noter lesquelles s'ouvrent, lesquelles sont fermées à clé, et lesquelles ne répondent pas du tout.
