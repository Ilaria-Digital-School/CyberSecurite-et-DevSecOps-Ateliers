# Analyser /var/log/auth.log pour détections

RAPPEL THÉORIQUE Le fichier /var/log/auth.log (sur les distributions Debian/Ubuntu ; son équivalent est /var/log/secure sur RHEL/CentOS) enregistre tous les événements liés à l'authentification et aux privilèges : connexions SSH réussies ou échouées, ouvertures de session, utilisations de sudo, création d'utilisateurs, modifications de mots de passe. C'est la source de vérité numéro un pour détecter une intrusion sur un système Linux. Le modèle mental à retenir : chaque ligne est un événement horodaté, produit par un service (souvent sshd, sudo, su, useradd), avec un message décrivant l'action. Analyser ce log revient à filtrer le bruit pour isoler les signaux d'attaque. Les patterns clés à connaître : 'Failed password for' (échec d'authentification), 'Accepted password' ou 'Accepted publickey' (connexion réussie), 'Invalid user' (tentative sur un compte inexistant, signe typique de brute-force), 'sudo: ... COMMAND=' (exécution de commande privilégiée), et 'authentication failure' pour les modules PAM. Erreurs fréquentes : confondre un échec isolé (utilisateur qui se trompe) avec une attaque (dizaines d'échecs en quelques secondes depuis une même IP) ; oublier que les logs peuvent être rotés (auth.log.1, auth.log.2.gz) ; analyser sans corréler l'heure, l'IP source et le compte ciblé. Mini-exemple : la ligne 'Jan 12 10:15:02 srv sshd[2048]: Failed password for invalid user admin from 203.0.113.45 port 44210 ssh2' indique une tentative de brute-force sur le compte inexistant 'admin' depuis 203.0.113.45. Compter ces lignes par IP permet de repérer instantanément un attaquant. --- ÉNONCÉ DU WORKSHOP Vous êtes analyste sécurité junior.
