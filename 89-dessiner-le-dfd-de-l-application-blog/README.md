# Dessiner le DFD de l’application Blog

RAPPEL THÉORIQUE Un Data Flow Diagram (DFD) est une représentation graphique de la façon dont les données circulent à travers une application. Il ne décrit pas le code, mais les mouvements de données entre les composants. Le DFD repose sur quatre symboles fondamentaux : l'entité externe (rectangle ou double carré) représente un acteur qui interagit avec le système sans en faire partie (utilisateur, navigateur, service tiers) ; le processus (cercle ou rectangle arrondi) représente une transformation des données (authentifier, créer un post) ; le magasin de données (deux lignes parallèles ou cylindre) représente un stockage (base de données, cache, fichiers) ; le flux de données (flèche orientée) représente le déplacement d'une donnée d'un élément à un autre. Le mental model à retenir : « Qui envoie quoi, à qui, et où c'est stocké ? » L'élément clé pour la modélisation des menaces est la frontière de confiance (trust boundary), une ligne pointillée qui sépare deux zones de niveaux de confiance différents (par exemple, entre Internet et votre serveur). C'est précisément là que STRIDE s'applique le plus, car chaque flux traversant une frontière est un point d'attaque potentiel. Erreurs fréquentes : confondre un processus avec un magasin de données ; oublier d'orienter les flèches ; dessiner l'architecture technique (serveurs, ports) au lieu des flux de données ; omettre les frontières de confiance, ce qui rend le DFD inutile pour la suite.
