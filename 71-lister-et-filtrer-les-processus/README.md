# Lister et filtrer les processus

RAPPEL THÉORIQUE Un processus est une instance d'un programme en cours d'exécution. Chaque processus possède un identifiant unique (PID), un processus parent (PPID), un propriétaire (utilisateur/groupe), un état (running, sleeping, zombie, stopped) et consomme des ressources (CPU, mémoire). Le noyau Linux organise les processus en arborescence : tout descend de PID 1 (init ou systemd). Le mental model à retenir : sous Linux, « tout est visible ». Vous pouvez inspecter en temps réel qui exécute quoi, avec quels droits et depuis quand. En sécurité, cette visibilité est cruciale pour détecter un processus suspect (mineur de crypto, reverse shell, binaire lancé depuis /tmp). Les commandes clés : 'ps' fournit un instantané (snapshot) des processus. 'ps aux' liste tous les processus de tous les utilisateurs avec propriétaire, %CPU, %MEM et commande complète. 'ps -ef' donne une vue orientée hiérarchie (PPID visible). 'top' et 'htop' offrent une vue dynamique et interactive. 'pgrep' et 'pidof' retrouvent des PID par nom. 'pstree' affiche l'arborescence. Erreurs fréquentes : confondre 'ps aux' (syntaxe BSD) et 'ps -ef' (syntaxe UNIX) ; oublier que 'ps' est un instantané figé (un processus court peut disparaître entre deux appels) ; filtrer avec 'grep' sans exclure la ligne du grep lui-même. Mini-exemple : pour trouver tous les processus liés à SSH triés par consommation mémoire : ps aux --sort=-%mem | grep [s]sh Le crochet [s] évite que grep se liste lui-même dans les résultats. --- ÉNONCÉ DU WORKSHOP Vous êtes analyste sur un poste Linux potentiellement compromis.
