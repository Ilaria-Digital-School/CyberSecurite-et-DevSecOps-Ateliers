# Analyser une sortie traceroute

**Rappel théorique** Traceroute (ou tracert sous Windows) est un outil de diagnostic réseau qui cartographie le chemin emprunté par les paquets IP entre votre machine et une destination. Il exploite le champ TTL (Time To Live) de l'en-tête IP : chaque routeur traversé décrémente ce TTL de 1 ; quand il atteint 0, le routeur renvoie un message ICMP « Time Exceeded » à l'émetteur. En envoyant des paquets avec TTL=1, 2, 3, etc., on obtient une réponse de chaque saut successif, révélant son adresse IP et la latence aller-retour. Le modèle mental à retenir : traceroute opère principalement à la couche 3 (Réseau) du modèle OSI. Chaque ligne de sortie représente un routeur intermédiaire (un saut). Les trois valeurs de temps (en ms) correspondent à trois sondes envoyées pour ce même saut, permettant d'évaluer la stabilité de la latence. Une étoile (*) signifie que la sonde n'a pas reçu de réponse dans le délai imparti : cela peut indiquer un pare-feu bloquant ICMP, un routeur configuré pour ne pas répondre, ou une perte de paquets. Erreurs fréquentes : confondre une étoile avec une panne totale (un saut silencieux peut quand même laisser transiter le trafic), ne pas distinguer la latence normale d'un saut intercontinental d'un vrai problème de performance, ou ignorer les asymétries de routage (le chemin retour peut différer du chemin aller). Mini-exemple : `3 192.168.1.1 1.2 ms 1.1 ms 1.3 ms` → le 3e saut est le routeur 192.168.1.1, très proche (latence < 2 ms, stable). ---...
