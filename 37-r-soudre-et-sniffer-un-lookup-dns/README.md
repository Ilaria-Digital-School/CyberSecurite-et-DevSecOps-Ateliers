# Résoudre et sniffer un lookup DNS

**Rappel théorique** Le DNS (Domain Name System) est le système qui traduit un nom de domaine lisible par un humain (ex : google.com) en adresse IP routable sur le réseau (ex : 142.250.74.46). Sans DNS, chaque connexion nécessiterait de connaître l'adresse IP de destination à la main. Le protocole DNS fonctionne principalement sur le port 53, en UDP pour les requêtes simples, en TCP pour les réponses volumineuses ou les transferts de zone. Une résolution DNS suit une chaîne hiérarchique : résolveur local (cache système) → résolveur récursif (souvent celui du FAI ou de l'entreprise) → serveurs racine → serveurs TLD (.com, .fr…) → serveur faisant autorité pour le domaine. Les types d'enregistrements DNS les plus courants sont : A (IPv4), AAAA (IPv6), CNAME (alias), MX (messagerie), NS (serveur de noms), TXT (informations texte, SPF, DKIM…). Une erreur fréquente chez les débutants est de confondre le résolveur récursif (qui fait le travail de chercher la réponse) avec le serveur faisant autorité (qui détient la vérité pour un domaine). Une autre erreur classique est d'oublier que le cache DNS (local ou distant) peut masquer la vraie résolution en cours. Exemple concret : quand vous tapez `ping cybersec-lab.local` dans un terminal Linux, votre OS consulte d'abord `/etc/hosts`, puis `/etc/resolv.conf` pour identifier le résolveur DNS, et envoie une requête UDP vers ce résolveur sur le port 53.
