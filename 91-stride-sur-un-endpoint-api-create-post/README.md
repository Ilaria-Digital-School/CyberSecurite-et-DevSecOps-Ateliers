# STRIDE sur un endpoint API "create post"

RAPPEL THÉORIQUE STRIDE est une méthode de modélisation des menaces qui classe les risques en six catégories : Spoofing (usurpation d'identité), Tampering (altération de données), Repudiation (répudiation, impossibilité de prouver une action), Information Disclosure (divulgation d'informations), Denial of Service (déni de service) et Elevation of Privilege (élévation de privilèges). Le mental model à retenir : pour chaque composant ou flux de données de votre application, vous vous demandez systématiquement « qu'est-ce qui pourrait mal tourner selon chacune des six lettres ? ». STRIDE ne cherche pas à corriger, mais à recenser les menaces de façon exhaustive et structurée. Les erreurs fréquentes des débutants : confondre une menace (ce qu'un attaquant tente) avec une vulnérabilité (la faiblesse exploitée) ; oublier d'analyser les flux de données et non seulement les composants ; ranger une menace dans la mauvaise catégorie (par exemple confondre Tampering et Elevation of Privilege) ; ou encore rester trop vague (« l'API peut être piratée ») au lieu d'être concret. Mini-exemple sur un endpoint de connexion : Spoofing = un attaquant réutilise un token volé pour se faire passer pour un utilisateur ; Information Disclosure = les messages d'erreur révèlent si un email existe. Vous voyez la logique : une menace précise, rattachée à une lettre, décrivant un scénario réaliste. ---- ÉNONCÉ DU WORKSHOP Vous avez déjà appliqué STRIDE sur un flux d'authentification. Vous montez maintenant d'un cran en analysant un endpoint API métier : POST /api/posts, qui permet à un utilisateur authentifié de créer un article de blog....
