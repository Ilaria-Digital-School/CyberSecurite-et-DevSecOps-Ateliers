# Atelier renforcé : appliquer les bonnes pratiques à hello.py

**Rappel théorique** Un script Python destiné à la sécurité n'est pas un simple fichier texte : c'est un outil qui peut être exécuté avec des privilèges élevés, manipuler des secrets (clés API, mots de passe, tokens), interagir avec le réseau et produire des journaux sensibles. Négliger les bonnes pratiques dès les premières lignes de code crée des vecteurs d'attaque évidents : un shebang mal configuré expose le script à des interpréteurs non maîtrisés, des secrets codés en dur dans le code source se retrouvent dans les dépôts Git, des droits trop larges sur le fichier permettent à n'importe quel utilisateur système de le lire ou de le modifier. Le mental model à adopter est celui du principe du moindre privilège appliqué au code : chaque élément (fichier, variable, processus) ne doit disposer que des droits strictement nécessaires à son fonctionnement. Les erreurs les plus fréquentes chez les débutants sont : (1) écrire `password = "monmotdepasse"` directement dans le script, (2) oublier le shebang ou utiliser `#!/usr/bin/python` au lieu de `#!/usr/bin/env python3`, (3) laisser le script lisible par tous avec `chmod 644` alors qu'il contient des secrets, (4) ignorer la gestion des exceptions lors des appels réseau ou fichier. Mini-exemple : au lieu de `api_key = "abc123"`, on utilise `import os; api_key = os.environ.get("API_KEY")` et on stocke la valeur réelle dans une variable d'environnement ou un fichier `.env` exclu du dépôt via `.gitignore`. --- **Énoncé de l'atelier** Dans les activités précédentes, vous avez écrit plusieurs scripts Python (scanners de ports, wrappers...
