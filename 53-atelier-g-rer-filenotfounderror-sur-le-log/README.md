# Atelier : gérer FileNotFoundError sur le log

**Rappel théorique** En Python, lorsqu'un programme tente d'ouvrir un fichier qui n'existe pas, l'interpréteur lève automatiquement une exception de type `FileNotFoundError`. Sans mécanisme de protection, cette erreur fait planter le script brutalement — ce qui est inacceptable dans un contexte d'automatisation en cybersécurité, où les scripts doivent être robustes et continuer à fonctionner même en cas de fichier manquant ou de chemin incorrect. La structure `try / except` permet d'intercepter ces exceptions et d'y répondre de façon contrôlée. Le bloc `try` contient le code risqué. Si une exception survient, Python saute immédiatement dans le bloc `except` correspondant. On peut cibler précisément `FileNotFoundError` pour ne pas masquer d'autres erreurs non prévues. Le bloc optionnel `else` s'exécute si aucune exception n'a été levée, et `finally` s'exécute dans tous les cas (utile pour fermer des ressources). Erreur fréquente : utiliser un `except` trop générique (`except Exception`) qui avale toutes les erreurs sans distinction et rend le débogage très difficile. Mini-exemple : ```python try: with open('access.log', 'r') as f: contenu = f.read() except FileNotFoundError: print("Erreur : le fichier de log est introuvable.") ``` Ce pattern est fondamental pour tout script d'analyse de logs en sécurité. --- **Énoncé de l'atelier** Dans l'atelier précédent, vous avez écrit un script Python capable de lire un fichier de log et de compter les lignes contenant le mot `ERROR`.
