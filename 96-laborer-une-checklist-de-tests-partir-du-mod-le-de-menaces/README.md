# Élaborer une checklist de tests à partir du modèle de menaces

RAPPEL THÉORIQUE Une checklist de tests de sécurité est le pont opérationnel entre la modélisation des menaces (ce qui peut mal tourner) et l'action concrète du testeur (comment le vérifier). Le mental model à retenir est simple : chaque menace identifiée dans votre modèle doit se traduire par au moins un test vérifiable, avec un critère de réussite/échec explicite. On part donc du triptyque déjà vu dans les activités précédentes : Surface d'attaque → Menaces (STRIDE) → Score de risque (OWASP Risk Rating), puis on descend d'un cran vers le test. STRIDE vous rappelle les six catégories : Spoofing (usurpation), Tampering (altération), Repudiation (répudiation), Information disclosure (divulgation), Denial of service (déni de service), Elevation of privilege (élévation de privilège). Chaque catégorie appelle des tests différents : un risque de Spoofing sur l'authentification appelle des tests de bruteforce, de gestion de session et de réinitialisation de mot de passe ; un risque de Tampering appelle des tests de manipulation de paramètres et d'injection. Les erreurs fréquentes : rédiger des tests vagues (« vérifier que l'authentification est sécurisée » n'est pas testable), tester sans lien avec un risque priorisé (on perd du temps sur du faible impact), et oublier le critère d'acceptation. Un bon item de checklist est atomique, reproductible et relié à une menace scorée.
