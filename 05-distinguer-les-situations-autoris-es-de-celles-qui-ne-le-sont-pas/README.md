# Distinguer les situations autorisées de celles qui ne le sont pas

Rappel théorique : Le principe clé de l'autorisation écrite En cybersécurité offensive légale et en hacking éthique, une règle fondamentale sépare la légalité de l'illégalité, le test professionnel de la cybercriminalité. Cette règle concerne la notion d'autorisation écrite, préalable et spécifique. Le modèle mental à adopter est simple : tout accès, toute modification, toute analyse technique d'un système informatique qui ne vous appartient pas est strictement interdite par la loi, sauf si vous pouvez prouver que son propriétaire légitime vous y a autorisé par écrit, pour une action et un périmètre précis. Les définitions clés sont les suivantes. L'autorisation est une permission formelle, délivrée par écrit, avant l'action, par une personne ayant le pouvoir légal de la donner. Une situation autorisée est une action pour laquelle une telle permission explicite existe. À l'inverse, une situation non autorisée est une action réalisée sans cette base légale, quelles que soient les intentions, même bonnes. L'erreur fréquente consiste à croire qu'une intention éthique, un environnement de laboratoire personnel ou un objectif d'apprentissage suffisent à rendre une action légale. C'est faux. Une autre erreur est de confondre une politique de sécurité générale (comme un programme de bug bounty public) avec une autorisation écrite, personnelle et circonstanciée pour un test spécifique. Un mini-exemple chiffré : si vous découvrez une vulnérabilité sur le site web d'une entreprise sans avoir signé de contrat avec elle, vous n'êtes pas autorisé à exploiter cette faille, même pour prouver son existence. Votre seule voie légale est de signaler cette découverte...
