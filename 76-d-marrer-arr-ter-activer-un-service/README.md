# Démarrer, arrêter, activer un service

RAPPEL THÉORIQUE Sous Linux moderne, la gestion des services repose sur systemd, le gestionnaire de services et le processus PID 1 qui pilote le démarrage du système. Un service est décrit par une « unité » (fichier .service) qui indique quoi lancer, comment, dans quel ordre et avec quelles dépendances. La commande centrale est systemctl. Le mental model à retenir : il faut distinguer deux notions différentes. « Démarrer » (start) lance immédiatement un service pour la session courante. « Activer » (enable) crée un lien symbolique pour que le service se lance automatiquement au prochain démarrage. Un service peut donc être actif maintenant mais non activé au boot, et inversement. Les états clés à surveiller avec `systemctl status ` sont : active (running) le service tourne ; inactive (dead) il est arrêté ; enabled/disabled indique s'il démarrera au boot ; failed signale une erreur. Le journal des services se consulte avec `journalctl -u `. Erreurs fréquentes : confondre start et enable (le service redisparaît après reboot), oublier `systemctl daemon-reload` après avoir modifié une unité, ou lancer les commandes sans droits root (utiliser sudo). Mini-exemple : `sudo systemctl start ssh` démarre SSH tout de suite, `sudo systemctl enable ssh` le rend persistant au boot, `sudo systemctl status ssh` confirme l'état, et `sudo systemctl stop ssh` l'arrête. En sécurité, savoir désactiver un service inutile réduit la surface d'attaque.
