# Analyser une requête HTTP dans Wireshark

**Rappel théorique** HTTP (HyperText Transfer Protocol) est un protocole de la couche application (couche 7 du modèle OSI) qui fonctionne en mode requête/réponse. Le client envoie une requête HTTP (méthode GET, POST, PUT, DELETE…) vers un serveur, qui renvoie une réponse contenant un code de statut (200, 301, 404, 500…) et un corps de message. HTTP repose sur TCP (couche 4) pour garantir la livraison des paquets, et par défaut sur le port 80 (443 pour HTTPS). Une requête HTTP est composée d'une ligne de requête (méthode + URL + version), d'en-têtes (Host, User-Agent, Content-Type…) et éventuellement d'un corps. Mental model clé : chaque échange HTTP que vous voyez dans Wireshark est encapsulé dans un segment TCP, lui-même dans un paquet IP, lui-même dans une trame Ethernet. Wireshark vous permet de remonter ces couches une par une. Erreur fréquente : confondre le flux TCP (la connexion) avec la transaction HTTP (la requête/réponse). Un flux TCP peut contenir plusieurs échanges HTTP (HTTP/1.1 avec keep-alive). Mini-exemple : lorsque votre navigateur charge http://example.com, il initie d'abord un handshake TCP (SYN, SYN-ACK, ACK), puis envoie la requête GET / HTTP/1.1, et le serveur répond HTTP/1.1 200 OK suivi du HTML. Wireshark capture chacun de ces paquets séparément, mais le filtre http vous permet d'isoler uniquement les échanges applicatifs. --- **Énoncé de l'atelier** Dans cet atelier, vous allez capturer et analyser en profondeur une requête HTTP réelle avec Wireshark. L'objectif est de comprendre concrètement comment les données circulent entre un client et un serveur web,...
