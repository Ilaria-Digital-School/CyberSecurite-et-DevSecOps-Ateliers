# chmod numérique 755/644

**Rappel théorique** Les permissions Linux définissent qui peut lire (r=4), écrire (w=2) ou exécuter (x=1) un fichier ou répertoire. La notation numérique (octale) additionne ces valeurs pour trois catégories : propriétaire (user), groupe (group) et autres (others). Ainsi, chmod 755 signifie : propriétaire = 7 (rwx), groupe = 5 (r-x), autres = 5 (r-x). chmod 644 signifie : propriétaire = 6 (rw-), groupe = 4 (r--), autres = 4 (r--). Le modèle mental à retenir : chaque chiffre est la somme de r(4), w(2), x(1) pour une catégorie donnée. Erreurs fréquentes : confondre permissions de répertoire et de fichier (un répertoire sans x est inaccessible même si r est présent), appliquer 777 par défaut 'pour que ça marche' (pratique dangereuse en cybersécurité), oublier que chmod ne change pas le propriétaire (c'est chown). Mini-exemple : un script shell deployé sur un serveur web doit être lisible et exécutable par le serveur (www-data), mais modifiable uniquement par le propriétaire. La commande chmod 755 mon_script.sh est appropriée. En revanche, un fichier de configuration contenant des secrets ne doit être accessible qu'au propriétaire : chmod 600 config.env est le bon réflexe. **Présentation de l'atelier** Cet atelier vous place dans la peau d'un administrateur système junior chargé de sécuriser l'arborescence d'une application web fictive déployée sur un serveur Linux.
