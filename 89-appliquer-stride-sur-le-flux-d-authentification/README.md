# Appliquer STRIDE sur le flux d’authentification

RAPPEL THÉORIQUE STRIDE est un modèle de classification des menaces développé par Microsoft. Chaque lettre correspond à une catégorie de menace et à la propriété de sécurité qu'elle viole : Spoofing (usurpation d'identité, viole l'authentification), Tampering (altération de données, viole l'intégrité), Repudiation (répudiation, viole la non-répudiation/traçabilité), Information Disclosure (divulgation d'information, viole la confidentialité), Denial of Service (déni de service, viole la disponibilité), et Elevation of Privilege (élévation de privilège, viole l'autorisation). Le mental model est simple : pour chaque élément d'un flux (processus, flux de données, dépôt de données, entité externe), on se demande systématiquement « quelles menaces STRIDE s'appliquent ici ? ». L'erreur fréquente numéro un est de confondre menace et vulnérabilité : une menace est un scénario d'attaque potentiel (« un attaquant tente de deviner le mot de passe »), pas une faille technique précise. Deuxième erreur : appliquer STRIDE à l'application entière sans décomposer le flux, ce qui produit une analyse floue. Troisième erreur : oublier de relier chaque menace à une contre-mesure concrète. Mini-exemple : sur l'étape « l'utilisateur envoie ses identifiants au serveur », un Spoofing consiste à rejouer un jeton volé ; la contre-mesure serait des jetons de session signés et expirables, transmis via HTTPS.
