# Identifier interfaces et ports ouverts

RAPPEL THÉORIQUE Sur un système Linux, une interface réseau est le point de connexion entre la machine et un réseau (physique comme eth0, virtuelle comme lo pour le loopback, ou associée à des conteneurs/VPN comme docker0, tun0). Chaque interface possède une ou plusieurs adresses IP, un état (UP/DOWN) et des statistiques de trafic. Un port ouvert correspond à un service qui écoute des connexions entrantes sur une combinaison IP+port (ex. 0.0.0.0:22 pour SSH accessible de partout, 127.0.0.1:5432 pour PostgreSQL limité au local). Le mental model à retenir : une interface = une porte d'entrée physique/logique, un port en écoute = une fenêtre ouverte sur cette porte. Un port en LISTEN attend des connexions ; un port ESTABLISHED indique une connexion active. Les erreurs fréquentes : confondre un port en écoute sur 127.0.0.1 (local uniquement, faible risque) avec un port sur 0.0.0.0 (exposé à tout le réseau, risque élevé) ; oublier de vérifier IPv6 (::1 vs :::) ; croire que netstat est toujours disponible (il est déprécié, ss est le standard moderne). Mini-exemple : la commande `ss -tulnp` affiche les sockets TCP/UDP en écoute (LISTEN), sans résolution DNS, avec le processus associé. Une ligne `tcp LISTEN 0 128 0.0.0.0:22 ... users:(("sshd",pid=812))` signifie que sshd écoute sur le port 22, accessible depuis n'importe quelle interface.
