# Identifier les menaces STRIDE dans le DFD

RAPPEL THÉORIQUE La modélisation des menaces consiste à analyser une application avant qu'elle ne soit attaquée, afin d'anticiper les faiblesses. Le Data Flow Diagram (DFD) représente visuellement comment les données circulent dans le système : entités externes (utilisateur, service tiers), processus (code qui traite la donnée), flux de données (les échanges) et data stores (bases de données, fichiers). Chaque élément du DFD est une cible potentielle. STRIDE fournit une grille de lecture systématique pour ces cibles : Spoofing (usurpation d'identité), Tampering (altération des données), Repudiation (déni d'action), Information Disclosure (fuite d'information), Denial of Service (déni de service) et Elevation of Privilege (élévation de privilèges). Le mental model à retenir : chaque type d'élément du DFD est vulnérable à des catégories STRIDE spécifiques. Les entités externes sont surtout exposées au Spoofing et à la Repudiation. Les flux de données subissent Tampering, Information Disclosure et DoS. Les processus peuvent souffrir des six lettres. Les data stores sont sensibles à Tampering, Information Disclosure, DoS et Repudiation. Erreurs fréquentes : oublier de traiter les frontières de confiance (trust boundaries), qui sont l'endroit où les menaces se concentrent ; confondre une menace (le problème potentiel) avec une vulnérabilité concrète ; et se contenter d'une seule menace par élément alors qu'il faut être exhaustif. Mini-exemple : sur le flux « navigateur → API /login », un Tampering serait la modification du corps de la requête, une Information Disclosure serait l'interception du mot de passe en clair sur un canal non chiffré.
