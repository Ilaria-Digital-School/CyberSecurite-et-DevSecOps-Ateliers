# Installer votre première cible d'entraînement dans le laboratoire isolé

Rappel théorique et mise en contexte Le concept fondamental de votre laboratoire de cybersécurité est l'isolement sécurisé. Ce principe garantit que toutes vos expérimentations, y compris les attaques simulées, se déroulent dans un environnement totalement coupé de votre réseau personnel et des systèmes de production. Une machine virtuelle, configurée en mode réseau « Host-Only » ou « NAT interne », constitue la base de cet isolement. Cette configuration crée un réseau virtuel indépendant, où la machine cible et votre machine d'attaque peuvent communiquer sans aucun accès à Internet ou à vos autres appareils. L'intégrité de votre réseau principal est ainsi préservée. Une erreur fréquente réside dans le transfert de fichiers vers la machine cible isolée. Puisque celle-ci est déconnectée d'Internet, vous ne pouvez pas utiliser `wget` ou `git clone` depuis l'extérieur. La méthode standard consiste à utiliser les outils d'hébergement de fichiers de votre logiciel de virtualisation, comme les « dossiers partagés » de VirtualBox ou VMware, ou un stockage USB virtuel. Un mini-exemple chiffré illustre cela : vous configurez une VM avec 4 Go de RAM et un disque de 20 Go. Vous paramétrez l'adaptateur réseau en mode « Host-Only ». Vous activez ensuite un dossier partagé nommé `transfert` entre votre système hôte et la VM. Tout fichier placé dans `C:\transfert` sur l'hôte Windows devient accessible dans `/media/sf_transfert` à l'intérieur de la VM Linux, permettant un transfert sécurisé et isolé.
