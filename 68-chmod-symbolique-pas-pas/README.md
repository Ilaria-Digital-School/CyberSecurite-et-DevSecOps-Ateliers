# chmod symbolique pas à pas

**Rappel théorique** Les permissions Linux définissent qui peut lire (r), écrire (w) ou exécuter (x) un fichier ou un répertoire. Chaque ressource possède trois niveaux de permissions : le propriétaire (u, pour user), le groupe (g), et les autres (o, pour others). On peut aussi cibler tous à la fois avec a (all). La notation symbolique de chmod suit la syntaxe : chmod [qui][opérateur][permissions] fichier. Les opérateurs sont + (ajouter), - (retirer) et = (définir exactement). Exemple concret : chmod g+w rapport.txt ajoute le droit d'écriture au groupe sur le fichier rapport.txt. On peut chaîner plusieurs modifications en une commande : chmod u+x,o-r script.sh. Erreurs fréquentes à éviter : confondre u (user = propriétaire) avec l'utilisateur courant ; oublier qu'un répertoire nécessite le bit x pour être traversable (cd) même si r permet de lister son contenu ; utiliser chmod récursivement sans discernement sur des répertoires système, ce qui peut casser des droits critiques. Mental model utile : visualise un tableau 3x3 (u/g/o × r/w/x). chmod symbolique modifie des cases précises de ce tableau, sans toucher aux autres. C'est là sa force par rapport à la notation octale qui réécrit tout le tableau d'un coup. --- **Énoncé de l'atelier** Cet atelier te place dans la peau d'un administrateur système junior qui doit sécuriser un ensemble de fichiers et de répertoires sur un serveur Linux. Tu vas appliquer des permissions précises via chmod en notation symbolique, analyser les conséquences de chaque modification, et justifier tes choix dans un rapport synthétique. L'objectif...
