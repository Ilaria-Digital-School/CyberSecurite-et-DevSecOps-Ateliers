# Filtrer trafic UDP DNS

**Rappel théorique** DNS (Domain Name System) est le protocole qui traduit les noms de domaine lisibles (ex. : google.com) en adresses IP. Il fonctionne principalement sur UDP, port 53, car UDP est sans connexion, léger et rapide — idéal pour des échanges requête/réponse courts. Contrairement à TCP, UDP n'établit pas de handshake : le client envoie directement sa requête, le serveur répond. C'est pourquoi le trafic DNS est massivement UDP dans la réalité. Dans Wireshark, filtrer ce trafic est fondamental en cybersécurité : un attaquant peut exploiter DNS pour de l'exfiltration de données (DNS tunneling), du C2 (Command & Control), ou encore du cache poisoning. Savoir isoler et analyser les échanges DNS dans une capture réseau est donc une compétence de base indispensable. Erreurs fréquentes à éviter : confondre le filtre d'affichage Wireshark (`dns`) avec un filtre de capture BPF (`udp port 53`) — les deux existent mais s'appliquent à des moments différents. Autre piège : oublier que certaines requêtes DNS passent en TCP (réponses volumineuses, zone transfers AXFR) — ne pas en conclure que tout le DNS est UDP. Mental model : imaginez DNS comme un annuaire téléphonique interrogé en temps réel, où chaque coup de fil (requête) déclenche une réponse quasi-instantanée, sans négociation préalable. Mini-exemple : dans Wireshark, saisir `udp.port == 53` dans la barre de filtre d'affichage suffit à isoler tout le trafic DNS UDP d'une capture.
