# Manipuler le fichier hosts pour override

**Rappel théorique** Le fichier hosts est l'un des mécanismes de résolution de noms les plus anciens et les plus fondamentaux d'un système d'exploitation. Avant même que le système ne consulte un serveur DNS, il interroge ce fichier pour vérifier si un nom de domaine y est défini manuellement. Sur Linux et macOS, il se trouve à /etc/hosts ; sous Windows, à C:\Windows\System32\drivers\etc\hosts. Sa syntaxe est simple : une adresse IP suivie d'un ou plusieurs noms de domaine séparés par des espaces ou des tabulations. Le mental model à retenir est le suivant : le fichier hosts est une couche de résolution prioritaire par rapport au DNS. Concrètement, si vous écrivez '127.0.0.1 monsite.com' dans ce fichier, toute requête vers monsite.com sera redirigée vers votre propre machine, peu importe ce que répondrait le DNS public. C'est ce qu'on appelle un DNS override local. Erreurs fréquentes : oublier les droits root/administrateur pour modifier le fichier, ne pas vider le cache DNS après modification (sur Linux : sudo systemd-resolve --flush-caches ou sudo resolvectl flush-caches), confondre l'ordre de résolution (hosts avant DNS dans la plupart des configurations nsswitch.conf), et ajouter des espaces ou caractères invisibles qui rendent l'entrée invalide. Mini-exemple : en ajoutant la ligne '192.168.1.50 api.monapp.local', on redirige toutes les requêtes vers api.monapp.local sur la machine à l'adresse 192.168.1.50, sans toucher au DNS.
