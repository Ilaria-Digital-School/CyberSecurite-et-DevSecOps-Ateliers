# Rendre exécutable et planifier via cron

RAPPEL THÉORIQUE Sous Linux, un script Bash n'est qu'un fichier texte tant qu'on ne lui donne pas le droit d'exécution. La commande 'chmod +x script.sh' active ce droit, et le shebang en première ligne ('#!/usr/bin/env bash' ou '#!/bin/bash') indique quel interpréteur utiliser. Le mental model à retenir : un script exécutable = droit d'exécution (x) + shebang correct + chemin d'accès valide. On lance ensuite le script avec './script.sh' (chemin relatif) ou son chemin absolu. Pour l'automatisation, cron est le planificateur historique d'Unix. Chaque utilisateur possède sa 'crontab' (éditable via 'crontab -e', listable via 'crontab -l'). Une ligne cron suit le format : minute heure jour_du_mois mois jour_de_semaine commande. Par exemple, '30 2 * * * /home/user/backup.sh' exécute le script tous les jours à 02h30. Les journaux d'exécution se retrouvent souvent via 'journalctl -u cron' ou dans '/var/log/syslog'. Erreurs fréquentes : oublier le chmod +x, utiliser des chemins relatifs dans un script lancé par cron (cron a un PATH minimal et un répertoire de travail différent), ne pas rediriger la sortie (stdout/stderr) et donc perdre les erreurs, et confondre les cinq champs temporels. Mini-exemple sécurité : planifier un scan réseau quotidien avec nmap dont la sortie est horodatée et archivée, ce qui permet de comparer l'état du réseau dans le temps. ÉNONCÉ DU WORKSHOP En cybersécurité, l'automatisation des tâches de surveillance est essentielle : un scan de ports planifié, une sauvegarde de configuration régulière ou une collecte d'état système permettent de détecter les dérives et de garder des preuves horodatées....
