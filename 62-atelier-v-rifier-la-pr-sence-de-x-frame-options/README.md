# Atelier : vérifier la présence de X-Frame-Options

**Rappel théorique** L'en-tête HTTP X-Frame-Options est un mécanisme de sécurité côté serveur qui contrôle si une page web peut être intégrée dans un élément , ou par une autre page. Son absence expose l'application à une attaque de type Clickjacking : un attaquant superpose une iframe invisible sur un bouton légitime pour piéger l'utilisateur en lui faisant effectuer une action à son insu (validation d'un virement, modification d'un compte, etc.). Les valeurs possibles sont DENY (aucun framing autorisé), SAMEORIGIN (framing autorisé uniquement depuis la même origine) et ALLOW-FROM uri (déprécié). Son successeur moderne est la directive Content-Security-Policy: frame-ancestors, mais X-Frame-Options reste très répandu et attendu dans les audits de sécurité. L'erreur fréquente des débutants est de confondre l'absence de cet en-tête avec une vulnérabilité critique immédiate : la criticité dépend du contexte applicatif (une page de login sans X-Frame-Options est bien plus grave qu'une page marketing). Mini-exemple : une requête GET sur https://example.com retourne les en-têtes ; si aucun X-Frame-Options ni frame-ancestors n'apparaît, la page est potentiellement frameable.
